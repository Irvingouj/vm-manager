§ 1 · Who it is for

One environment, set up by IT, built on by everyone.

Platform administrators

Install it once: one image and one Compose file start the platform beside a bundled Postgres 18 and a reverse proxy that terminates TLS with your wildcard certificate. People sign in with your company's identity provider (OIDC); their Groups come from it.

Installing with Compose →

Builders

An employee who creates and deploys an Application, normally by directing a coding agent. No authentication to write, no credentials to manage, no infrastructure to provision: the platform supplies them.

Getting started →

Coding agents

AI generates application logic; the platform supplies the governed environment. Agents use the tool's commands, each with --json, and the project's AGENTS.md tells them how to work in it.

§ 2 · How it works

From nothing to an Application open in a browser.

  1. Make a project

    vibe new makes a project from the template. vibe check says whether it will deploy, with each problem and its fix.

    vibe new hello
cd hello
npm install
vibe check

  2. Run it on your computer

    vibe dev serves the Application to your browser as a test User you choose, with test rows, beside a private Postgres. Open http://hello.localhost:7480/.

    vibe dev
vibe request --as outsider /

  3. Deploy it

    vibe deploy builds the Application on your computer from its last commit and sends it as a new Version, which goes live at https://hello.vibe.example.com/.

    git add --all
git commit -m "The first version"
vibe deploy

  4. Share it

    It opens for its Contributors alone until one of them shares it with people, Groups or everyone, with vibe share or on the Dashboard.

    vibe share hello --email colleague@example.com
vibe share hello --group engineering
vibe share hello --everyone

§ 3 · Governed by default

The context is the platform's. The records are the platform's.

Every operation an Application makes carries a Trusted context: which User, which Application, which request. Application code receives it and cannot construct one. An Application reads and writes a shared database only as its Grants allow, as the person who uses it.

Every operation of an Application on a shared database is in the Operation log, and every row it changes in its own database is in the Change history, with who did it and through which Application.

The SDK's types →

// manifest.ts
export default defineManifest({ name, description, resources })
// src/index.ts
export default defineApp(manifest, { fetch(request, ctx) { ... } })

ctx.user().db("devops")  // a shared database, as the User
ctx.user().ownDb()       // its own database, as the User
ctx.app().ownDb()        // its own database, as the Application
