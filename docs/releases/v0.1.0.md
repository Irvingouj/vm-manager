# vibe 0.1.0

The first release of the platform: a minimal one, to try it for real. It holds the platform's image, the Compose files that install it, and the tool `vibe` for Linux and macOS. [Getting started](https://github.com/Irvingouj/vm-manager/blob/v0.1.0/docs/getting-started.md) takes you from nothing to an Application open in your browser.

**This release is not for untrusted Applications or real company data.** Use it with Applications you wrote yourself and with data you can lose. It stays so until the work on three things is done: the credentials of shared databases (kept encrypted, revoked, replaced), the limits on what one request of an Application may use, and the hardening of the runtime that runs Applications.

## What works

- **Installing.** One image and one Compose file start the platform beside a bundled Postgres 18 and a reverse proxy that terminates TLS with your wildcard certificate. You can use your own reverse proxy or your own Postgres 18 instead. Upgrading keeps every database, the OIDC connection and the sessions.
- **Signing in.** People sign in with your company's identity provider (OIDC). Their Groups come from it. Platform administrators are the members of one Group you name. The tool signs in through the browser.
- **Making an Application.** `vibe new` makes a project from the template. `vibe check` says whether it will deploy, with each problem and its fix. `vibe generate` writes the next migration of the Application's own database, and stops before a migration that destroys data.
- **Shared databases.** A Builder lists the Resources (`vibe resources`) and pulls one's structure into the project as a typed definition (`vibe pull`). An Application reads and writes a Resource only as its Grants allow, as the person who uses it.
- **Running it on your computer.** `vibe dev` serves the Application to your browser as a test User you choose, with test rows, beside a private Postgres. `vibe request` sends it one request.
- **Deploying.** `vibe deploy` builds the Application on your computer and sends it as a new Version, which goes live at `https://<name>.<domain>/`. `vibe versions`, `vibe go-back` and `vibe logs` show the Versions, serve an earlier one again, and show what the Application printed.
- **Sharing.** Contributors may change and deploy an Application. It opens for them alone until one of them shares it with people, Groups or everyone (`vibe share`).
- **The Dashboard** lists the Applications you contribute to and those shared with you, says what of each will not work for you, and lets a Contributor share one.
- **Records.** Every operation of an Application on a shared database is in the Operation log, and every row it changes in its own database is in the Change history, with who did it and through which Application.

## What is missing

These are not in this release. Each is planned.

- Shared databases' credentials are kept in the platform database without encryption. Registering a Resource is done through the platform's API only: the tool has no command for it, nor for listing, changing or revoking Grants.
- There are no limits per request yet: one Application can use as much CPU time, memory and time as it likes, and so slow down the others.
- The runtime that runs Applications is not yet closed against every way an Application could stop the whole program.
- An Application cannot call services outside the platform (`fetch` to the internet).
- An Application cannot serve static files: its pages are strings in its code.
- An Application cannot be deleted.
- An Application's source is not kept on the platform: it stays in your own Git repository.
- Platform administrators cannot yet see every Application, disable one, or read the Operation log with the tool.
- There is no report of Applications built against an older structure of a shared database that has changed.
- Coding agents use the tool's commands; there is no MCP interface yet.
- The program does not serve TLS itself: the Compose file's proxy, or your own, does.
- The tool is not on npm, and there is no Windows build.
- Reviews found smaller things still to be done in the identity and capture of operations, in the Application's own database, in the SDK's values, and in long histories.

## Systems

- **The image** is for `linux/amd64` only. There is no image for `linux/arm64`.
- **The tool** is built for two targets:
  - `x86_64-unknown-linux-gnu`: Linux on x86-64 with glibc 2.35 or later (Ubuntu 22.04, Debian 12 and later). It was built on Ubuntu 22.04.
  - `aarch64-apple-darwin`: macOS on Apple silicon. It is not signed by a developer and not notarised by Apple: downloaded with a browser, macOS holds it back until you remove its quarantine mark (`xattr -d com.apple.quarantine vibe`).
- **What was tried.** On Linux, the whole set of tests of the project and the install tests ran before the release was published. The release's runner has 4 cores, fewer than the machines the tests' time limits are sized for, so there the tests ran all side by side once, and each test file that failed that way ran once more alone, one test at a time, and had to pass; the release's log names each file that needed it. On macOS, nothing was run but what the release workflow runs there: the tool was built, unpacked, said its version, made a project, sent it one request on the machine, and passed `vibe check` against an installation on the same machine. Running it locally, deploying and signing in were not tried on a Mac by a person.
- **The Postgres a local run downloads.** `vibe dev` and `vibe request` download Postgres 18 once, for the Application's own database on your computer. It is a third party's build (zonky's embedded Postgres binaries, from Maven Central), not the PostgreSQL project's own. The tool checks it against the checksum (SHA-256) it carries before it unpacks it.

## The files

- `compose.yaml`, `compose.own-proxy.yaml`, `compose.own-postgres.yaml`, `env.example`: the Compose files and the list of values (`.env.example` in the repository).
- `vibe-0.1.0-x86_64-unknown-linux-gnu.tar.gz`, `vibe-0.1.0-aarch64-apple-darwin.tar.gz`: the tool, with the licences of what it is built from.
- `SHA256SUMS`: the SHA-256 of each file. Check your downloads with `sha256sum --check --ignore-missing SHA256SUMS` (Linux) or `shasum -a 256 --check --ignore-missing SHA256SUMS` (macOS).
- The image: `ghcr.io/irvingouj/vibe:0.1.0`.
